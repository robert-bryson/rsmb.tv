# Tornado Tracks

Route: `/projects/tornado-tracks/map`

## Status

MVP shipped. Core features implemented:

- Full-screen MapLibre map at `/projects/tornado-tracks/map`
- NOAA/NCEI StormEvents automated sync pipeline (`syncTornadoes.js`)
- Per-year GeoJSON split under `public/data/tornadoes/tracks/{year}.geojson`
- Density (heatmap) mode uses `public/data/tornadoes/track-points/{year}.geojson`
- Annual summary and notable events JSON pre-baked at build time
- EF-scale filter, region presets (CONUS / Midwest / Plains / Dixie Alley)
- Year range timeline with play/pause animation
- Scale, year, and decade color modes
- Trends panel: annual sparkline with OLS regression, frequency-vs-fatality dual-metric chart, decade comparison bar chart, top-states breakdown
- WebGL fallback SVG renderer for environments without GPU support
- All filter state stored in URL params for shareability
- Share button copies the current URL to the clipboard

## Data storage

Tornado data is stored in S3 (`rsmbtv-temperature-data` bucket, `tornadoes/`
prefix) and served via the existing `data.rsmb.tv` CloudFront distribution —
the same infrastructure used for temperature records.

- In production: `https://data.rsmb.tv/tornadoes/…` (CDN-served)
- In development: `/data/tornadoes/…` (local `public/` directory)

Generated files are **gitignored** (`public/data/tornadoes/`). The CI workflow
(`sync-tornadoes.yml`) runs the sync script, uploads results to S3, and
invalidates CloudFront — it does **not** commit to the repo.

GeoJSON files are served with `Content-Type: application/geo+json` (RFC 7946).
JSON summary files use `Content-Type: application/json`.

## Architecture

```
src/features/tornadoes/
  components/
    TornadoMap.tsx          # Main map component + SVG fallback
    TornadoSummaryPanel.tsx # Right-side stats + filters + trends panel
    TornadoTimeline.tsx     # Bottom timeline + year range controls
  hooks/
    useTornadoData.ts       # Per-year GeoJSON fetching with cache
    useTornadoFilters.ts    # URL-param filter state
  utils.ts                  # Pure utility functions (tested)
  constants.ts              # Colors, URLs, region state lists
  types/index.ts            # All TypeScript types
projects/tornado-tracks/
  scripts/
    syncTornadoes.js        # NOAA/NCEI StormEvents sync + GeoJSON generation
public/data/tornadoes/      # gitignored — generated by sync, served from S3/CDN
  tracks/{year}.geojson     # LineString per tornado (1950-present)
  track-points/{year}.geojson  # Point per tornado (for density mode)
  annual-summary.json
  state-summary.json
  notable-events.json
```

## Sync pipeline

```bash
# Run from repo root
node projects/tornado-tracks/scripts/syncTornadoes.js
# Or via the top-level backfill script:
node scripts/backfill.js --projects tornadoes
node scripts/backfill.js --projects tornadoes --storage local,s3
```

Fetches the latest NOAA/NCEI StormEvents CSVs, normalizes F/EF scale labels,
drops rows without valid coordinates, and writes per-year GeoJSON + summary
JSON to `public/data/tornadoes/`. The sync is designed to be run as a scheduled
job (monthly is sufficient for historical data; weekly for current-year freshness).

StormEvents CSV files are cached in `.cache/tornado-tracks/` between runs to
avoid redundant network downloads.

In CI (`sync-tornadoes.yml`), output is uploaded to S3 instead of committed.

## Backfill

To populate data from scratch (all years, 1950–present):

```bash
# Write output locally only:
node scripts/backfill.js --projects tornadoes

# Write locally and upload to S3 + invalidate CloudFront:
node scripts/backfill.js --projects tornadoes --storage local,s3 \
  --bucket rsmbtv-temperature-data --cdn-id <DISTRIBUTION_ID>

# Using environment variables (recommended):
TORNADO_DATA_BUCKET=rsmbtv-temperature-data \
TORNADO_DATA_CDN_ID=<DISTRIBUTION_ID> \
  node scripts/backfill.js --projects tornadoes --storage local,s3
```

See `scripts/backfill.js` for full option documentation.

## Trend analytics

The Trends panel (`mode=trends`) shows four views computed client-side from
loaded tracks and the pre-baked `annual-summary.json`:

- **A · Annual count vs selection** — bar chart with OLS trend line and
  comparison pills (Avg/yr, Deaths/yr, EF2%) for the selected range vs full
  history. The current in-progress year is excluded to avoid skewing downward.
- **B · Frequency vs fatality rate** — overlaid bar + line chart showing how
  annual count has risen while deaths-per-100-tornadoes has fallen.
- **C · Decade comparison** — horizontal bar chart by decade, toggle between
  Avg/yr, Deaths/yr, EF2+%, and Deaths per 100.
- **D · Top states** — horizontal bar chart of the most affected states in the
  selected year + scale filter window, toggle between Count, EF2+%, and Deaths.

## Known limitations

- Tracks are start→end straight lines, not damage-path swaths. DAT survey
  polygons would improve modern events but require a separate data layer.
- EF0 count trends are noisy (reporting practices changed over time). Filtering
  to EF1+ improves trend interpretation.
- WebGL is unavailable in WSL without GPU passthrough; the SVG fallback handles
  this automatically.
- `state-summary.json` is generated and stored in S3 but not yet consumed by
  the frontend (state breakdown is computed client-side from loaded tracks).
